# ADR 0003: Python target and reproducible backend dependencies

- Status: accepted
- Date: 2026-10-02
- Scope: `backend/`

## 1. Python target: `>=3.12`

**Search.** Before Phase 2A the repository had no backend and no Python configuration. It was
searched twice (the second time for this ADR): no `pyproject.toml`, `.python-version`,
`.tool-versions`, `runtime.txt`, `requirements*.txt`, `Pipfile`, `Dockerfile`, docker-compose, CI
workflow or host config existed on `develop` or in history, and no document names a Python version.
The architecture blueprint says "Python (FastAPI)", "Pydantic v2" and names a free web host as the
prototype target, but states no Python version.

**Decision.** There is no inherited target, so this is a new decision rather than a change:
`requires-python = ">=3.12"` in `backend/pyproject.toml`.

**Why 3.12.** It is a mainstream, fully supported runtime for FastAPI, Pydantic v2 and the
type-checking tools used here, with a comfortable support window; the code uses `X | None`, `Self`,
`StrEnum` and modern typing, which need 3.11+. The floor is deliberately not the newest release, so
a typical hosting platform can run it.

**Evidence.** The test suite, `ruff` and strict `mypy` pass from the lockfile on CPython 3.12.15 and
3.13.5; CI runs both. Changing the floor needs a new ADR.

## 2. Reproducible dependencies: `uv.lock`

**Problem.** `pyproject.toml` has lower-bound pins only, so two installs on different days can differ.

**Decision.**

- `pyproject.toml` remains the single source of declared dependencies (including the `dev` extra).
- [`backend/uv.lock`](../../backend/uv.lock) is generated by `uv lock` from the real resolved graph.
  It is committed. It is a universal lock: one file covers Linux, macOS and Windows and the whole
  `>=3.12` range, with file hashes.
- Install from it with `uv sync --locked --extra dev`. `--locked` fails if the lock no longer
  matches `pyproject.toml`; CI also runs `uv lock --check`.
- CI installs from the lock on each Python in the matrix (the uv version is pinned in the workflow).

**Why uv.** The alternatives either lock only the platform they run on (`pip-compile` run on Windows
would omit Linux-only packages and be re-run per Python) or are experimental (`pip lock`).
`uv lock` produces one cross-platform lock honouring `requires-python`, and was the only option that
let the 3.12 and 3.13 CI jobs install the identical, hashed set. It adds one developer/CI tool and no
runtime dependency; the project still builds with plain pip/setuptools.

**Workflow.** Edit `pyproject.toml` -> `uv lock` -> commit both. Upgrade with `uv lock --upgrade`
and run the full checks.

**Not done.** No Docker image or deployment pinning yet; that belongs to the deployment phase.
